## What the programme is testing

HERMES asks whether a world model latent trained only on task relevant prediction can match
a latent trained on pixel reconstruction, while carrying less irrelevant detail. The practical
stake is cost: if reward prediction alone is sufficient, the pixel decoder that dominates
training cost in reconstruction based world models is optional.

Experiment 2 showed a task only latent matching a reconstruction latent while carrying about
twelve times less background information. That result has an obvious objection: in Experiment
2 colour never mattered, so a model that discarded all colour would have scored identically.
Experiment 3 exists to remove that objection, in three ways.

1. The agent is steered by continuous actions, so the model has to imagine the consequences of
   acting, which is what a world model is for.
2. Relevance is defined by reward rather than by a coordinate chosen by hand. The task loss is
   reward prediction, so whatever predicts return is task relevant by construction.
3. Relevance is made selective. One piece of colour is essential and another is useless, so a
   model that discards colour wholesale now fails visibly.

## The environment

A 32 by 32 RGB frame. A white Gaussian blob is the agent, steered by a continuous action in
two dimensions. Two static goals sit in the frame, a black hollow ring and a black plus, at
least 0.35 of the frame apart. The background hue decides which goal pays: hues 0.05 to 0.45
make the ring pay, 0.55 to 0.95 make the plus pay, and the bands around both boundaries are
never drawn. Two fully saturated coloured blobs bounce around as distractors and never affect
reward. Reward is dense, `r = -d + 0.5 exp(-d² / (2 · 0.05²))`, where `d` is the distance to
the goal that currently pays.

Two design decisions are worth stating in the post because they were checked rather than
assumed.

The goals are black shapes rather than coloured ones. A goal with a fixed colour disappears
against a background of the same hue, and using shape leaves colour meaning exactly two
things: the background, which is relevant, and the distractors, which are not.

The dynamics carry momentum: `v' = 0.95 v + 0.0025 a`, position clipped at the walls, velocity
zeroed on contact. The damping value was chosen by simulation before any network existed. With
damping 0.90, a planner that looks one step ahead reaches 92 percent of the best achievable
return, so a world model would be pointless. At 0.95 it reaches 76 percent. The full run
confirmed this on the real task: an oracle restricted to one step of planning scores 0.738 on
the normalised scale, against 1.000 for the same oracle planning ten steps ahead. A second
oracle that has perfect state but cannot see the background scores 0.506, so ignoring the
selector costs about half the achievable return. Both numbers are in
`hermes_exp3_v3_medium_results/planning_summary.csv`.

## The four arms

Every arm shares an identical convolutional encoder, an action conditioned GRU and a reward
head. All arms start from byte identical weights, which is asserted in code at runtime, and
train on the same batches in the same order. They differ only in the extra loss, each weighted
1.0.

| arm | extra loss | what it stands for |
| :--- | :--- | :--- |
| A | pixel reconstruction from the latent | DreamerV3, in its loss |
| B | none, no decoder is built | MuZero style value equivalence |
| C | predict only irrelevant factors: a distractor occupancy heatmap, background saturation and brightness | negative control |
| D | predict the future latent of an exponential moving average target encoder | TD-MPC2 latent consistency, JEPA |

The latent passes through a LayerNorm with no learnable gain in every arm. Every arm uses a
deterministic GRU rather than a recurrent state space model, because such a model's KL term is
itself a representation loss and would stop arm B from being reward only.

## Evaluation, in three levels

Level 1 is reward prediction on held out behaviour episodes, R² for horizons 0 to 15 given the
true actions, against three references: predict the mean, hold the current reward, and a
predictor that has true future positions but cannot see the selector.

Level 2 is planning return, and it is the headline. 200 fixed episodes, cross entropy method
planning inside each latent with 500 samples, 50 elites, 6 iterations and a 10 step horizon,
replanning every step. Six baselines: no action, random actions, an oracle on true state with
the same planner, that oracle restricted to one step, that oracle with the background hidden,
and that oracle aimed at the wrong goal. Return is reported raw and on a normalised scale where
the no action baseline is 0 and the oracle is 1.

Level 3 is latent probes. Linear and multilayer perceptron probes on the encoder latent and on
the GRU state, split by episode, with two references: the untrained shared starting weights,
and a convolutional network of the same architecture trained directly on frames to read each
factor. That second reference is the positive control. A target the control cannot read is
reported as untestable rather than as dropped. The headline statistic is selectivity, the R² of
the goal that pays minus the R² of the goal that does not.

## The narrative spine: three iterations

This is the structure the post should follow. Each version fixed what the previous one exposed,
and one of the fixes turned out to be harmful, which the third version proved.

### v1

Three seeds. Reward only training learned the colour signal cleanly: arms B, C and D headed for
the goal that pays 99 to 100 percent of the time, against 52 percent for a planner with perfect
state that cannot see the background. Arm B reached 0.528 on the normalised return scale and
stopped 3.4 px from the goal.

Five things blocked any claim, all visible in the run's own outputs. Arm A was still training
when the fixed epoch budget ran out, so "A is worse" could not be separated from "A is slower".
The two sharpest probes had no dynamic range: the inactive goal and the distractor positions
read 0.00 from every latent including the untrained weights, so there was no way to distinguish
"B dropped it" from "nothing could read it". The negative control never learned its own
auxiliary target, so irrelevant content was never actually forced into its latent. Planning
return was measuring exploitation rather than selection, because every arm's imagined reward
was systematically optimistic. The distribution shift test moved return by at most 0.006,
because no latent encoded the distractors at all.

### v2

Four fixes. Train to a held out plateau instead of a fixed epoch count, and report the epochs
needed as its own metric. Add the trained convolutional ceiling as a positive control. Change
the negative control's target to an identity free occupancy heatmap, because the previous
target asked for each distractor by slot and slots have no stable identity. And, to address the
exploitation problem, add offline episodes driven by the evaluation planner itself aimed at a
goal chosen by a coin flip, so that the dataset covers the approach and stop states the planner
actually visits. I verified before the run that this fourth change leaks nothing: the coin flip
goal agrees with the goal that pays 0.4996 of the time over 40 seeds by 4000 episodes.

Everything regressed. Arm B fell from 0.528 to 0.190 on the normalised scale, its goal choice
from 0.988 to 0.700, and its stopping distance from 3.4 px to 10.3 px. Arm D fell from 0.591 to
0.350. Two further faults surfaced. The new stopping rule ended four of twelve runs while they
were still on the initial plateau with held out R² at or below zero, and then labelled them
converged, because a flat plateau looks converged. And the positive control was not a ceiling
for every target: it read the distractor heatmap at 0.24 while arm C read the same target at
0.70 to 0.83, because one network trained on thirteen target groups at once underserves some of
them. v2 had changed the data, the stopping rule and the control's target together, so the cause
of the regression was not identified. The parking data was the leading suspect and nothing more.

### v3

Five fixes. Patience only starts counting once a run has actually learned, with a higher minimum
epoch count, and runs that never learn within the ceiling are reported as such instead of as
converged. One ceiling network per target group, with a validity flag raised automatically for
any target an arm reads better than the ceiling does. No criterion is judged on fewer than three
usable paired seeds. Five seeds instead of three. And a paired ablation: arms B and D trained
twice per seed, once with the parked episodes and once without, compared on identical planning
episodes.

## The results to report

### Finding one: the parked data I added in v2 is harmful. This is the strongest result.

Paired by seed, on the seeds where both versions passed the learning gate. Source:
`hermes_exp3_v3_medium_results/ablation_parking.csv` and section 7b of its `VERDICT.txt`.

| | B with parking | B without | D with parking | D without |
| :--- | :--- | :--- | :--- | :--- |
| goal choice accuracy | 0.735 | 0.998 | 0.911 | 1.000 |
| stopping distance | 9.28 px | 3.00 px | 6.51 px | 2.57 px |
| optimism bias at one step | 0.410 | 0.174 | 0.287 | 0.130 |
| reward RMSE on planner trajectories | 0.410 | 0.167 | 0.286 | 0.135 |
| learning gate passes | 3 of 5 seeds | 5 of 5 | 4 of 5 | 5 of 5 |
| reward R² at one step | 0.475, sd 0.552 | 0.909, sd 0.028 | 0.758, sd 0.424 | 0.929, sd 0.016 |

Parking helps in 0 of 3 usable seeds for B and 0 of 4 for D, on both goal choice and stopping
distance. The run's own verdict line is: "parking hurts in every usable seed".

Three independent things agree with the ablation, and the post should say so, because a single
ablation on three seeds is not much on its own.

First, an earlier notebook agrees. v1 had no parked data, and its arm B reached normalised
return 0.528 with goal choice 0.988 and a 3.43 px stopping distance. v3's arm B without parked
data reaches 0.556, 0.994 and 3.15 px in a separate notebook with a different stopping rule and
five seeds instead of three. Source: `hermes_exp3_medium_results/planning_summary.csv` and
`hermes_exp3_v3_medium_results/planning_summary.csv`.

Second, the sharpest single comparison is within one seed. On seed 0, with identical
architecture and identical starting weights, arm B trained with parked data plans at chance:
normalised return -0.011 and goal choice 0.455, where 0.500 means it cannot tell the two goals
apart. The same arm on the same seed without parked data reaches normalised return 0.599 and
goal choice 1.000. Source: `hermes_exp3_v3_medium_results/planning_per_seed.csv`.

Third, the mechanism is visible in training rather than inferred. On seed 0, arm B with parked
data drives its training reward error from 0.888 at epoch 10 down to 0.079 at epoch 120, while
held out R² at 15 steps falls from -0.028 to -0.697. The same seed without parked data converges
by epoch 60 with held out R² at 0.757. Seed 3 shows the same pattern. The latent never collapsed
in either case, with per dimension spread between 0.78 and 0.89 and effective rank between 21
and 28, so this is not representation collapse, and the training error falling monotonically
rules out a failure to fit. It is memorisation. The likely reason, which the post should present
as the proposed explanation and not as a measured fact, is that parking the agent on the goal
puts about 15 percent of all steps inside the reward bonus radius, which makes the reward
distribution bimodal with a hard spike at exactly +0.5. Sources:
`hermes_exp3_v3_medium_results/training_log.csv`,
`hermes_exp3_v3_medium_results/training_level1_snapshots.csv`,
`hermes_exp3_v3_medium_results/leakage_check.csv`.

The honest framing: I added planner generated data to fix a real problem, the fix made the
experiment worse in every measurable way, and it took a third iteration with a paired ablation
to establish that rather than assume it.

### Finding two: reward only training strips irrelevant background detail that reconstruction keeps.

This now replicates in all three runs, and in v3 it is measured against a positive control that
reads the same target at 0.99, so the test is known to be meaningful. Probe R² for background
saturation and brightness, and for the shade within the hue band. Source:
`hermes_exp3_v3_medium_results/latent_probes.csv`, section 5 of `VERDICT.txt`.

| target | control | untrained weights | A | B | C | D |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| background saturation and brightness | 0.99 | 0.66 | 0.59 | 0.00 | 0.04 | 0.07 |
| shade within the hue band | 1.00 | 0.74 | 0.72 | 0.14 | 0.00 | 0.69 |

Arm B reads 0.00 for saturation and brightness in all five seeds. Arm A reads 0.46 to 0.67
across the five. For the shade within the band, arm B reads 0.00 in all three usable seeds. The
untrained starting weights carry this information, so B is actively discarding something it
began with, not failing to acquire it.

### Finding three: the controls now behave, which is what makes the first two findings readable.

The negative control demonstrably learns its irrelevant target: arm C reads the distractor
occupancy heatmap at 0.81 against a control ceiling of 0.90, while arm B reads it at 0.01. Every
probe target is valid except distractor positions by slot, where the run flags its own ceiling
as invalid because arm C reads the target better than the ceiling does, and distractor hues,
which nothing can read at all. Source: `hermes_exp3_v3_medium_results/ceiling_validity.csv`.

Two guardrail checks, both worth a short mention because they were bugs found and fixed before
any science was run. Imagination retains 0.505 of its starting state after 15 imagined steps
with a keep state bias of +3.0 added to the GRU update gate, against 0.001 with the default
initialisation, meaning the default network forgets its starting state within about four steps.
And the behaviour policy leaks nothing: the goal that pays cannot be predicted from the agent's
movements alone, at 0.515 with logistic regression and 0.493 with boosted trees, against a
chance band of 0.500 plus or minus 0.031 over 1000 episodes. Sources:
`hermes_exp3_v3_medium_results/retention.csv` and `leakage_check.csv`.

### What the experiment set out to test and did not resolve

State this plainly and give it real space in the post. It is the part that makes the rest
credible.

1. Arm A versus arm B is a tie. The return difference is +0.037 against a spread across seeds of
   0.070, and the difference in how much reward accuracy is lost over the horizon is +0.0006 R².
   C versus B and D versus B are ties too. Only three seeds are usable for the paired comparison.
   Source: sections 2 and 3 of `hermes_exp3_v3_medium_results/VERDICT.txt`.
2. Worse, arms A and C were never trained without the parked data, so the only A versus B
   comparison available sits in the configuration the ablation has just shown to be harmful.
3. Selectivity does not separate A from B. The goal that does not pay is readable in principle,
   at 0.96 by the control, and every trained arm drops it entirely, reading 0.00 to 0.02. Arm A
   is more selective than arm B in two of the three usable seeds, so the criterion I stated in
   advance, that B beats A in every usable seed, fails. The run's own verdict for this section
   is "mixed".
4. Reconstruction does not draw the small objects, which caps what A versus B can show in this
   environment. Contrast retained against each image's own background region: agent 0.34, goals
   0.21, distractors 0.11. The decoder recovers the background colour and a blurred agent and
   largely omits the ring, the plus and the distractors. So the premise "reconstruction encodes
   everything" is false here. Source: `hermes_exp3_v3_medium_results/recon_fidelity.csv`.
5. The planner still exploits the model. Reward error at one step rises from 0.175 on behaviour
   data to 0.513 on the planner's own trajectories for arm A, and from 0.213 to 0.573 for arm B,
   with the optimism bias accounting for almost the whole error. Removing the parked data cuts
   the bias to 0.174 and 0.130 but does not remove it. Source: section 7 of `VERDICT.txt` and
   `planning_optimism.csv`.
6. The distribution shift test is uninformative. Four shifts, at most 0.013 change in mean
   return. Since no arm except the negative control encodes the distractors, this measures
   indifference rather than robustness. Source: `shift_summary.csv`.
7. Eleven of thirty runs did not converge within the 120 epoch ceiling. Every one of them was
   trained to the full ceiling and labelled "never learned within the ceiling" rather than
   called converged, which is the v3 stopping rule working as designed. The arms without parked
   data passed on the same seeds where the parked arms failed, which is what identifies the data
   as the cause rather than the rule.

### Cost

The whole v3 run is 158 GPU minutes across 30 networks on one Colab GPU. On the seeds where both
arms learned, arm A averaged 6.24 minutes over 73 epochs and arm B averaged 3.76 minutes over 80
epochs, which is 0.085 minutes per epoch against 0.047, so the pixel decoder costs about 80
percent more time per epoch. Arm B without parked data converged in 60 to 100 epochs and 2.81 to
4.70 minutes. Source: `hermes_exp3_v3_medium_results/learning_speed.csv`.

### What comes next

One change, chosen because the ablation identified it: set the parked share to zero for all four
arms, keep everything else fixed, and read A versus B for the first time in a configuration that
is not known to be broken. That configuration already passes the learning gate in five of five
seeds, with goal choice between 0.994 and 1.000 and a standard deviation across seeds of 0.028 on
reward R² against 0.552 for the parked version, so it is both the correct configuration and the
cheaper one.
Secondary: raise the epoch ceiling for the negative control, which converged in only one of five
seeds even at 120 epochs.
